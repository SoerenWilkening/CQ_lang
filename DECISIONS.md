- 2026-11-12, owner, result of a deferred output call (amends rule 16, CR 821-825; WITHDRAWS Q1 of 2026-11-11 parts 1 to 3; pass, bundle and checker work now, the CR edit follows). Criterion: no value the lowered program reads may depend on whether the backend defers a call. An output call is a pure part (formatting, counting, encoding) plus a write; only the write is an effect, so only the write goes to the tape. A case not named is decided from this criterion and musl's source. (1) For every C library output call the pass classifies as a host effect, a result the program reads is never the entry's rail: it is the value musl's body returns when every write succeeds, computed in the circuit by ordinary lowered code; the effect goes to the tape with no result. Nothing is emitted for an unread result, except for a format that may hold %n, as today.
