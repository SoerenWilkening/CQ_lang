## Round-2 clone creation: analytic audit and empirical limit

Successful round-2 clone creation/mask growth was **not dynamically exercised in this round**, because both new shapes stopped at an earlier main-control gap. Do not turn the two declines into success evidence. The following argument covers the code path instead.

`repropagateControlMerges` builds its reseed set from UntaintedMergeRails plus new taint and runs onward control to fixpoint before `adjudicateTaintDelta` (`TaintPropagation.cpp:2769`, `:2819`). The latter first calls `replanReseedSpecialization`, then `detectSpecializations` using the live delta (`:2658-2659`). Replan recomputes the actual argument mask (`:2512`), reclassifies with it (`:2523`), and updates `Cand.Mask` (`:2525`) on accept; failures are loudly diagnosed and removed from Pending. Detection handles candidates whose original mask was zero.

`specialize` drains the resulting Pending plan only after `runControlChain` finishes in both entry points. Every unresolved `(callee,mask)` is passed through `resolveSite` to `buildClone`. `buildClone` unconditionally creates/records/seeds the clone (`Specialization.cpp:554-561`), then unconditionally runs `lowerCloneControl` (`:569`) before deferred signature retype, nested drain, opcode lowering and wrapping. `lowerCloneControl` unconditionally runs both StageList drivers (`:246`, `:284`). There is no round-number branch or earlier control-stage opportunity that a later-created clone must have caught. Cache keys include the mask, so a grown mask cannot accidentally reuse the earlier mask's clone; cache hits reuse only a fully built same-mask record. This establishes the full-stage property for round-2 candidates independently of when the main plan learned their mask.
