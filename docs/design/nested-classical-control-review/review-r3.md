## Findings and corrections

1. **P1: a matching body does not establish a matching calling convention.** The initial ordinary-call contract did not compare the call instruction with the definition. An exact `fastcc` leaf returning its parameter could be reached by a plain `ccc` nested call inside an otherwise pure scalar outer function. A guarded source invocation can leave that call untaken; unconditional speculation then executes a mismatched ABI. LLVM 19.1 defines such a dynamic calling-convention mismatch as undefined behavior. The corrected `basicCallContractHolds` compares the two conventions for the root and every nested call. `control_predmux_nested_classical_callconv.ll` isolates a matching outer call with a mismatched inner call. This was an analytic counterexample; no new lowering was executed. [LLVM 19.1 calling conventions](https://releases.llvm.org/19.1.0/docs/LangRef.html#calling-conventions).

2. **P1: ordinary nested calls skipped poison-generating call flags.** The initial graph walk applied `canCreateUndefOrPoison` to arithmetic and intrinsic calls but only the attribute contract to ordinary calls. An exact leaf returning a literal quiet NaN is total; an inner `call nnan` of that leaf creates poison. An outer `noundef` return observes the poison and has immediate UB even for defined parameters. Dropping the moved root call's flags cannot change the instruction inside the retained original callee. The shared basic contract now rejects LLVM's owning `hasPoisonGeneratingFlags` and `hasPoisonGeneratingMetadata` predicates at every call. The separately proved ordinary return range remains eligible. `control_predmux_nested_classical_callflags.ll` isolates this case. No measured pre-fix acceptance is claimed. [LLVM 19.1 fast-math flags and poison](https://releases.llvm.org/19.1.0/docs/LangRef.html#fast-math-flags).

3. **P1: curated intrinsic semantics do not discharge an immediate-UB call contract.** The intrinsic fast path initially bypassed the ordinary contract completely. A retained scalar outer function could call `llvm.sqrt.f64` with `noreturn`, then return the result. The intrinsic computes a defined result but returns in violation of that effective contract; speculative execution can introduce UB on a source-untaken arm. The corrected graph walk applies `basicCallContractHolds` before splitting intrinsic and ordinary calls. It checks effective noreturn, returns-twice, convergence, noduplicate, musttail, bundles, conventions and poison flags/metadata in both cases. `control_predmux_nested_intrinsic_noreturn.ll` pins this distinction. This is analytic reasoning, not an executed witness. [LLVM 19.1 function attributes](https://releases.llvm.org/19.1.0/docs/LangRef.html#function-attributes).

4. **Correction hazard: an intrinsic declaration cannot prove a return range by an empty body walk.** Reusing the ordinary return proof on an intrinsic declaration would vacuously accept any range because the declaration contains no `ret`. The implementer instead added `intrinsicContractHolds`: both return-attribute homes must be inert, poison-generating return attributes are rejected, and parameter homes allow inert attributes plus a constant `immarg`. The existing curated intrinsic poison predicate still checks ctlz/cttz/abs's poison immarg. A lying ctpop range is isolated by `control_predmux_nested_intrinsic_range.ll`. This was a risk in applying the preceding correction; this report does not assert that the initial `canCreateUndefOrPoison` path accepted that range.

All four corrections were read in the current 292-line helper. The tests named above were read only, and their execution results remain the implementer's validation obligation.

## Speculation and marker reasoning

The strict owning body query establishes exact linked definitions, acyclic CFG/call graphs, no conditional branches or memory, and only safe constant integer divisors. The new proof adds defined-result and effective-contract obligations rather than treating poison analysis as immediate-UB analysis. Both new graph/SSA walks use visited iterative worklists.

All scalar arguments of an admitted speculative ordinary call are stabilized, including an unconstrained outer parameter which later feeds an inner noundef parameter. Definedness is proved from the producer graph without context or use assumptions. Source marking includes scalar producer dependencies outside the moved arm. Argument gate literals are covered by the function mark. Replacing constant uses is restricted to instructions in the same function, so module-uniqued constants cannot introduce cross-function SSA references. The emitted-call owner recognizes aliases.

A surviving scalar definition gets its freeze immediately afterward, a PHI after the PHI group, and an argument or constant at entry. The original definition already dominated its legal local uses. One replacement rewrites the relevant local forward/inverse operands. Clone stabilization occurs before capture; main stabilization occurs after adjoints in both entry points. Freeze is the identity on defined selected-arm inputs; an untaken arm uses an arbitrary stable literal whose scratch computation is removed by the corresponding inverse.

I also challenged `literal()`'s use of LLVM's general guaranteed-non-poison query while original branches still exist. The current topological placement closes the simple circularity counterexample: a non-entry block's scalar body is moved into the entry before any successor needs its edge literal, leaving its old branch in the old block. LLVM's same-block UB-use inference cannot certify that moved condition from the old nested branch. An entry condition is source-observed whenever its region executes; outer predication handles later speculation. This is a placement argument, not a general claim that ValueTracking ignores UB-sensitive uses. No additional edge-literal blocker was established.

Raw poison/undef literals and other unimplemented cases outside the covered source-record path still rely on their existing loud backstops. Full p3kd.7.7, memory, aggregate and loop gaps remain outside this clearance.
