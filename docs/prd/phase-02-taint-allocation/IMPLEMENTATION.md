# Phase 2 Implementation Plan — IR pass: taint sources, gate-triggered allocation

Companion to [`PRD.md`](PRD.md). The PRD fixes *what* and *why*; this
document fixes *how, in what order, and how each step is proven*. It is
grounded in the current tree (commit on `taint-driven-pipeline`), not
just the PRD prose.

**Guiding constraints (from the request):**
1. **Modular** — one responsibility per translation unit; no module
   folded into another. The existing module seam (taint / rotation /
   opcode / measure / width-dispatch / driver) is preserved and
   extended, not collapsed.
2. **Test-driven** — every work package leads with the test that fails
   (RED), then the implementation that makes it pass (GREEN). Tests are
   first-class deliverables, authored before or with their code.
3. **≤ 300 LOC per module** — every hand-authored TU stays under 300
   lines. Budgets are tracked in §3. (`runtime/cq_templates.c` is
   autogenerated from `tools/opcode_table.yaml` and is out of budget;
   Phase 2 does not touch it.)

## 1. The one invariant that governs everything: handle typing

This is the single most error-prone aspect of the phase and is **not
spelled out in the PRD**, so it is stated first.

A `cq_theta_<sfx>` call returns the **natural ABI scalar type** of the
suffix — `i32` for `si32`, `double` for `f64`, `i8` for `si8`, etc.
(see `include/CQ.h`). A runtime **handle is always `i32`**
(`cqrt_alloc_<W>` returns `int32_t` for every width). So lowering a
non-`i32` theta replaces a value of one type (`double`) with a value of
another (`i32`).

LLVM `Value::replaceAllUsesWith` nominally requires matching types. The
retired `MidHandleRebind` already performed exactly this cross-type
RAUW: `%qdouble_mid_t = type { double }`, `extractvalue → double`,
RAUW'd with the `i32` alloc. It worked, and the new plain-SSA path
inherits the mechanism unchanged:

> **The cross-type RAUW is laundered by erasure.** Taint propagation
> guarantees every user of a tainted value is itself tainted, hence is
> itself lowered to a call that *consumes an `i32` handle* (a template
> call or `cqrt_measure_<W>`) and then **erased**. The transiently
> type-mismatched instruction (`fadd double %h_i32, …`) never survives
> to the verifier. The only tainted value that exits to a natural type
> is a `cqrt_measure_<W>` result, whose type already matches the
> original measure call's result. Net: the lowered module is
> verify-clean.

**Empirically confirmed for this toolchain** (do not re-litigate):
- `opt-19` / LLVM 19.1.7 is an **optimized, assertions-OFF** build
  (`llvm-config-19 --assertion-mode` → `OFF`), so the cross-type RAUW
  does not assert.
- Running the *current* `lowering_add_qq_f64.ll` and
  `lowering_measure_f64.ll` through the built pass yields
  `cqrt_alloc_f64` → `i32` handles, `cq_template_fadd_f64(i32, i32)`,
  `cqrt_measure_f64(i32) → double`, and **passes `-passes=verify`
  cleanly**.

**Consequences for the implementation:**
- `RotationLowering` RAUWs the theta result to the **handle**
  (`i32` alloc result, or the tainted operand) — never to the
  void `cqrt_ry`/`cqrt_rz` call (PRD §2.5). The handle's `i32` type may
  differ from the theta result's type; that is expected and correct.
- Every `*.ll` LIT fixture keeps its second RUN line
  (`… | %cq-opt -passes=verify -disable-output -`). **That RUN line is
  the standing guard for this invariant** — it is why the non-`i32`
  fixtures (`lowering_theta_alloc_f64`, the repointed `…_qq_f64` /
  `…_qc_f32`) are load-bearing, not redundant with the `i32` ones.
- **Risk if the toolchain ever moves to assertions-ON** (see §8, R5):
  the cross-type RAUW would assert. The fallback is a `Value* → i32`
  handle side-map (the old `RebindMap::StructToHandle` shape) consumed
  by `OpcodeLowering`/`MeasureLowering` instead of RAUW. Not built now;
  noted so the decision is on record.

**4.3 New module `RotationLowering`**

Header decl:
```cpp
namespace cq {
class WidthDispatch; struct TaintSet;
// Lower @cq_theta_<sfx> (alloc+ry / ry-only per §5.1 operand dispatch)
// and @cq_phi_<sfx> (rz on tainted / delete on classical). Seeds
// taint.BirthOrder for every minted handle. Mutates taint.Tainted.
void lowerRotations(llvm::Module &M, WidthDispatch &wd, TaintSet &taint);
}
```

Algorithm (single pass over the already-collected work lists — no module
re-walk; `ThetaCalls`/`PhiCalls` are populated by `propagate`):

```
suffixFromName(CI, "cq_theta_")  // strip prefix → "si32"; "" on mismatch

// THETA — iterate taint.ThetaCalls in collection (BB) order.
// Forward order matters: lowering theta N RAUWs its result, so a chained
// theta N+1 sees the handle as its operand at process time.
for theta in taint.ThetaCalls:
    sfx   = suffixFromName(theta, "cq_theta_");  abi = wd.abiWidthFor(sfx)
    ry    = wd.ryRtFn(abi)                       // skip+diagnose if empty
    op    = theta->getArgOperand(0)              // operand (re-read: RAUW-updated)
    angle = theta->getArgOperand(1)
    if op in taint.Tainted:                      // tainted → ry only
        emit  call void ry(op, angle)   before theta
        theta->replaceAllUsesWith(op)            // RAUW to the HANDLE (operand)
    else:                                        // classical → alloc + ry
        alloc = wd.allocFn(abi)
        h     = emit call i32 alloc(op)  before theta
        emit  call void ry(h, angle)     before theta
        theta->replaceAllUsesWith(h)             // RAUW to the HANDLE (alloc)
        taint.Tainted.insert(h)
        taint.BirthOrder[h] = taint.NextBirth++  // BB-order seed → stable Q+Q
    queue theta for erase

// PHI — iterate taint.PhiCalls (collected regardless of taint; §2.3).
for phi in taint.PhiCalls:
    sfx = suffixFromName(phi, "cq_phi_");  abi = wd.abiWidthFor(sfx)
    op  = phi->getArgOperand(0);  angle = phi->getArgOperand(1)
    if op in taint.Tainted:                      // tainted → rz
        rz = wd.rzRtFn(abi)
        emit call void rz(op, angle)     before phi
    // classical → no rz (Rz on a basis state is unobservable, §4.1)
    phi->replaceAllUsesWith(op)                  // RAUW to operand either way
    queue phi for erase

erase all queued calls
```

Notes:
- **Never RAUW to the `ry`/`rz` call** (void). RAUW to the handle/operand
  (§1, PRD §2.5).
- `BirthOrder` is seeded **only** for the alloc handle of a
  classical-operand theta — chained (tainted) thetas reuse the operand's
  existing slot; phi mints no handle. This reproduces the old
  `MidHandleRebind` seeding (one slot per alloc, BB order), which
  `OpcodeLowering` reads for clang-stable Q+Q canonicalization (§8 R2).
- Diagnostics: an unresolved suffix/width reuses the
  `DiagnosticInfoUnsupported` surface (mirror `MeasureLowering`) and
  leaves the call in place to surface at the verifier — loud, not silent.

**Removal + rewire (same commit):**
- `git rm ir-pass/src/MidHandleRebind.cpp ir-pass/include/MidHandleRebind.h`;

- `OpcodeLowering`: signature `lowerOps(M, wd, taint)` (drop

  taint.Tainted.count(StructArg)`); keep the "operand not recognized"
  diagnostic; remove `MidHandleRebind.h` include.
- `TaintPropagation`:
  - `resolveSources` resolves `thetaFn`/`phiFn`/`measureFn` into

### 6.1 `tests/frontend/cq_theta_o1_survival.c` (PRD §2.12)

Models `cq_invert_markers_survive.c` (4 RUN lines, `-O0`/`-O1`/`-O2`/
`-O3`, `CHECK-LABEL` to scope each function so inlining can't satisfy an
assertion from another caller):
```c
// RUN: %clang %cq_include -O0 -emit-llvm -include CQ.h -S %s -o - | %filecheck %s
// RUN: %clang %cq_include -O1 -emit-llvm -include CQ.h -S %s -o - | %filecheck %s
// RUN: %clang %cq_include -O2 -emit-llvm -include CQ.h -S %s -o - | %filecheck %s
// RUN: %clang %cq_include -O3 -emit-llvm -include CQ.h -S %s -o - | %filecheck %s

// cq_theta -O survival (PRD §2.12, §7.1). The externs carry no
// memory(...)/readonly/readnone attribute, so clang cannot CSE
// duplicate theta calls, DCE a dead-result theta, or break the chained
// data dependency at any -O level. A future CQ.h edit adding a purity
// attribute — silently dropping a qubit the user asked for — fails here.

int chained(int x) {
    x = cq_theta(x, 0.1);
    x = cq_theta(x, 0.2);          // consumes the 1st theta's result
    return cq_measure(x);
}
// CHECK-LABEL: define {{.*}} @chained
// CHECK:       call i32 @cq_theta_si32(
// CHECK:       call i32 @cq_theta_si32(

void dead_result(int x) {
    cq_theta(x, 0.3);              // result unused — must survive DCE
```

**`run_slice.sh`** (the 4-stage pipeline + byte-diff; temp dir,
`set -euo pipefail`, `trap` cleanup):
```bash
#!/usr/bin/env bash
set -euo pipefail
CLANG=$1 OPT=$2 PASS=$3 INC=$4 SRC=$5 RT=$6 TPL=$7 GOLDEN=$8
TMP=$(mktemp -d); trap 'rm -rf "$TMP"' EXIT
"$CLANG" -I"$INC" -include CQ.h -O1 -emit-llvm -S "$SRC" -o "$TMP/s1.ll"      # Stage 1
"$OPT" -load-pass-plugin "$PASS" -passes=cq-lowering -S "$TMP/s1.ll" -o "$TMP/s2.ll"  # Stage 2
"$CLANG" "$TMP/s2.ll" "$TPL" "$RT" -o "$TMP/slice"                            # Stage 3 (link)
"$TMP/slice" | diff -u - "$GOLDEN"
```
Link order is `templates` then `runtime`: `cq_template_add_i32_hl` (in
`libcq_templates`) calls `cqrt_alloc_handle` (in `libcq_runtime`), so
templates precede runtime for single-pass GNU `ld`.
