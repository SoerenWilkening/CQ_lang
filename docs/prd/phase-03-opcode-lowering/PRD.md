# Phase 3 PRD — IR pass: full opcode lowering

Phase-specific design decisions, scope, and done criteria for generalizing
`OpcodeLowering` from the Phase 2 `add`/`fadd` slice to the full 38-opcode
surface, across all four tainted instruction classes, with width ×
signedness × operand-shape fan-out. This is a lean PRD: it memorializes
the decisions resolved in PRD-discovery so the rationale survives between
sessions; the implementation plan (module layout, fixture generation,
commit shape) lands later as `IMPLEMENTATION.md` alongside this file.

## 0. Invariant recap (not new — the ground Phase 3 stands on)

The type model the lowering preserves, stated once so the decisions below
are unambiguous:

> **A quantum register reference is always an `i32` handle; a classical
> value is always its real C width. They cross only at named boundaries.**

| Role | Signature | Boundary |
|---|---|---|
| `cqrt_alloc_<W>` | `(real-width value) → i32` | C→Q entry |
| `cqrt_measure_<W>` | `(i32 handle) → real-width value` | Q→C exit |
| `cq_template_<op>_<W>_hl` | `(i32 handle, real-width classical) → i32` | mixed |
| `cq_template_<op>_<W>` / `_ry` / `_rz` / flag handle | `i32`(s) → `i32`/`void` | pure quantum |

Every tainted SSA value Phase 3 produces is therefore an `i32` handle;
real C widths reappear only at `cqrt_measure_<W>` and as the classical
operand of an `_hl`/`_lh` template. A comparison yields a **flag handle**
(`i32`, logically 1-qubit), never an `i1`.

## 1. Scope

**In scope.** Lower every tainted data opcode to its template call, across
four instruction classes:

- **`BinaryOperator`** — int arith (`add sub mul sdiv udiv srem urem`),
  int bitwise (`and or xor shl lshr ashr`), fp arith
  (`fadd fsub fmul fdiv frem`). Widths `{i1,i8,i16,i32,i64}` int /
  `{f32,f64}` fp.
- **`UnaryOperator`** — `fneg` × `{f32,f64}`.
- **`CmpInst`** — `icmp` × 10 predicates × int widths; `fcmp` × 6 ordered
  predicates × fp widths. Result is a flag handle.
- **`CastInst`** — `sext zext trunc fpext fptrunc sitofp uitofp fptosi
  fptoui` over the applicable width pairs (§ opcode table).

Operand shapes: **HH** (both tainted → base symbol), **HL** (handle +
literal → `_hl`), **LH** (literal + handle → `_lh`, **non-commutative ops
only**). Forward stems only — no `_inv`, no `_controlled` (later phases).

**Out of scope.** See §5. Load-bearing exclusions: controlled-form (Phase
4), uncomputation / `_inv` emission / `cqrt_free` (Phase 5), function
lifting (Phase 6), manual inversion (Phase 7), memory/`select`/`phi`-as-
data (memory-model phase), real template bodies (post-freeze).

## 2. Design decisions

Each was resolved during PRD-discovery and is binding.

### 2.1 Programmatic name-building, not a generated dispatch table

`WidthDispatch` builds template symbol names by a single pure function of
`(opcode-stem, width, predicate?, cast-pair?, shape)`. LLVM hands us the
exact stems the opcode table uses: `Instruction::getOpcodeName()` →
`"add"`/`"sub"`/`"fadd"`/`"shl"`/…, `CmpInst::getPredicateName(pred)` →
`"slt"`/`"une"`/`"oeq"`/…. The convention is
`cq_template_<op>[_<pred>]_<W>[_<from>_to_<to>][_hl|_lh]` (forward).

We do **not** generate or consume `OpcodeTables.cpp`. Rationale: the name
is fully derivable, so a 200-row lookup table encodes what a ~20-line
function computes; and a generated table would not have caught the
`une`/`one` bug (pass and header co-generated from the same wrong yaml
agree *and are both wrong*). The drift it would guard against is caught
instead by (a) per-(opcode,width,shape) LIT fixtures that FileCheck the
exact symbol, and (b) link against the autogenerated runtime header. The
naming convention is frozen at Phase 10, so the shared-contract risk is
near zero. `gen_templates.py` remains the authority for the runtime
header; the pass mirrors the *convention*, not a copy of the list.

A small hand-written **supported-set** (which opcodes / widths /
predicates / cast-pairs are in scope) drives the loud "no template"
diagnostic for anything outside the surface — same `DiagnosticInfoUnsupported`
surface `OpcodeLowering` uses today.

### 2.2 The four instruction-class walks

`TaintPropagation` already taints every user instruction, so `CmpInst`,
`UnaryOperator`, and `CastInst` already arrive tainted; today they hit the
"no template" path. Phase 3 adds a collection + dispatch arm for each
class. Collection remains up-front (before any rewrite) to sidestep
iterator invalidation under RAUW, exactly as the current `BinaryOperator`
path does.

### 2.3 Casts: capture from/to widths at collection time

A cast keys on `(from_width, to_width)` and changes the handle's ABI
width. **`CastInst::getSrcTy()` returns `getOperand(0)->getType()`**, so
once the operand is RAUW'd to an i32 handle the source width is lost.
Phase 3 therefore records `(CastInst*, fromWidth, toWidth)` **at
collection time**, before any lowering corrupts the operand type. Casts
are unary at the IR level → **no `_hl`/`_lh`**. Semantically (under stubs)
a cast template is naming + bookkeeping; widths round-trip through the
symbol stream, so no special handle-width tracking is owed to later
phases.

### 2.4 Operand canonicalization

- **Commutative** (`add mul and or xor fadd fmul`): a literal operand
  canonicalizes to the RHS → `_hl(handle, literal)`. Q+Q operands are
  ordered by `BirthOrder` (lower-birth → LHS) for clang-version-stable
  traces.
- **Non-commutative** (`sub sdiv udiv srem urem shl lshr ashr fsub fdiv
  frem`): operand order is semantic — **the BirthOrder swap is gated off**.
  A literal on the left lowers to the **`_lh`** template (decision 2.6);
  a literal on the right to `_hl`.
- **Compares**: a literal on the left canonicalizes by **predicate flip**
  (`slt↔sgt`, `sle↔sge`, `ult↔ugt`, `ule↔uge`, `olt↔ogt`, `ole↔oge`;
  `eq`/`ne`/`oeq`/`une` self-map) → reuse the existing `_hl` template. No
  `_lh` compare templates.

### 2.5 Signedness / flags are dropped (width-only ABI)

`add nsw`/`add nuw` both → `cq_template_add_i<W>`. Signedness that
*matters* is already carried by the distinct LLVM opcode (`sdiv` vs
`udiv`, `lshr` vs `ashr`) or predicate (`slt` vs `ult`), which map to
distinct symbols. The frontend signedness suffix (`si8`/`ui8`) was already
collapsed to width-only in Phase 2. No additional bridging in Phase 3.

### 2.6 `frem` in; `_lh` templates for the 11 non-commutative ops

`frem` joins fp_arith (→ 5 binary fp ops). `_lh` (`(real-width classical,
i32 handle) → i32`) is added for `sub sdiv udiv srem urem shl lshr ashr`
(int) + `fsub fdiv frem` (fp). These arise from ordinary C surviving
`-O1` — every unary integer negate is `sub …_lh` with literal 0;
`100/x → sdiv …_lh`; `3<<x → shl …_lh`. Commutative ops get no `_lh`
(canonicalize to `_hl`); compares get no `_lh` (predicate flip). These
additions regenerate the runtime header from `opcode_table.yaml`.

`frem` has no C-operator source (float `%` is illegal; it arrives only via
`fmod()`, a Phase 6 libm substitution) — so its lowering path is exercised
by a **hand-written `.ll`** fixture in Phase 3, not by C source.

### 2.7 `fcmp` predicate set: fix `one → une`

The accurate C float-comparison set is `{oeq, une, olt, ogt, ole, oge}`
(verified: `clang -O1` emits `fcmp une` for `!=`, not `one`). The yaml
ships `one`; the header has 8 dead `_one_` symbols and 0 `_une_`, so a
tainted `float != float` currently fails to link. Tracked as
`test_C_libtooling-7ws`; its fix is a Phase 3 precondition. (ROADMAP's "14
predicates" is superseded — C emits exactly 6.)

### 2.8 Phase 3 / Phase 4 seam: compares in data position only

A tainted compare is lowered **only when its result is in pure data /
measure position**. A compare result feeding a `br i1` *or* a `select i1`
is left untouched (it stays the original `i1`, IR stays well-typed) and is
owned by Phase 4 (the `select` case likely punts further to the
memory-model/select phase). The flag handle never reaches a terminator;
`br i32` exists at no point. A measured compare carries Clang's own
`zext i1→i32` bridge, which lowers to a `zext` cast template (2.3) that
widens the flag handle before `cqrt_measure_i32`.

### 2.9 Lower what `-O1` emits, not the C operators

`-O1` reassociates and canonicalizes aggressively (`100 - 3*s` →
`mul -3` + `add 100`; the C `-` and `*3` vanish). The pass operates on the
post-`-O1` opcode stream; fixtures are derived from **real `clang -O1`
output**, not from the source operators, so coverage reflects what the
pass actually sees.

## 3. Deliverables

- **`opcode_table.yaml`** — add `frem`; add `fwd_lh`/`inv_lh` variants to
  the 11 non-commutative binary ops; `one → une` in the `fcmp` predicate
  set (`test_C_libtooling-7ws`).
- **Runtime header/source** — regenerate `runtime/cq_templates.{h,c}` via
  `tools/gen_templates.py`; update the SHA preamble; CI verifies the hash.
- **`WidthDispatch`** — replace the `add`/`fadd`-specific `addTemplate`
  with a general `templateFn(stem, width, {pred|cast-pair}, shape)`
  resolver + the in-scope supported-set predicates.
- **`OpcodeLowering`** — collection + dispatch arms for `BinaryOperator`
  (all stems), `UnaryOperator` (`fneg`), `CmpInst` (`icmp`/`fcmp`, flag
  handle, predicate-flip, data-position gate), `CastInst` (early width
  capture). Commutativity-gated BirthOrder swap.
- **LIT fixtures** — one per (opcode, width, shape) green; skeletons may be
  generated, CHECK lines real. Plus a hand-written `frem` `.ll`.
- **e2e trace smokes** — at least the two Phase-3-rich programs sketched in
  PRD-discovery (Q+Q/`_hl` arithmetic; data-position compare + zext
  bridge), run-and-diff against golden logs.
- **Doc cross-links** — mark ROADMAP Phase 3 done-criteria coverage; note
  the `frem`/`fcmp` reconciliations against backend §6.3.

---

## 4. Done criteria

- Programs using the full operator set across mixed Q/C operands produce
  the expected `cq_template_*` call sequences; one LIT fixture per
  (opcode, width, shape) green.
- A tainted `float != float` lowers to `cq_template_fcmp_une_*` and links
  (`test_C_libtooling-7ws` closed).
- `_lh` programs (`-x`, `100/x`, `3<<x`) lower to `_lh` templates.
- A data-position tainted compare lowers to its flag-handle template +
  `zext`/`trunc` cast bridge; a compare feeding `br i1`/`select i1` is left
  untouched and passes `opt -verify`.
- Unsupported tainted opcodes/widths still emit the loud
  `DiagnosticInfoUnsupported` "no template" error.
- The two e2e trace smokes diff clean against their golden logs.

## 5. Out of scope

- **Controlled-form** `_controlled` lowering and tainted-`br` region
  recovery (Phase 4).
- **Uncomputation**: `_inv` emission via `emit_inverse`, `cqrt_free`
  (Phase 5). Phase 3 emits forward stems only.
- **Function lifting** / specialization (Phase 6); `frem`-from-`fmod` and
  other libm paths (Phase 6).
- **Manual inversion** brackets (Phase 7).
- **Memory & structural opcodes**: `load`/`store`/`getelementptr`,
  `select`, `phi`-as-data (memory-model phase).
- **Unordered `fcmp` predicates** and `-ffast-math`-only predicates (incl.
  `one`); the stage-1 floor is `-O1`, no fast-math.
- **Real template bodies** — all bodies stay trace-only stubs (post-freeze).
- **`OpcodeTables.cpp`** generation/consumption (decision 2.1).

## 6. Risks

- **Cast width capture (2.3).** If from/to widths aren't recorded before
  RAUW, `getSrcTy()` reports the corrupted post-lowering type → wrong/garbage
  symbol. Mitigation: capture at collection; LIT fixture per cast pair.
- **`-O1` reassociation surprises (2.9).** A C operator may not survive as
  the expected opcode. Mitigation: fixtures derived from real `-O1` output;
  the loud diagnostic surfaces any unhandled opcode rather than silently
  passing it through.
- **Compare feeding both data and a branch.** Rare; the data use wants
  lowering, the branch use wants Phase 4. Resolution deferred to Phase 4
  (it owns the structure); Phase 3 leaves such compares untouched.
- **`_lh` surface growth vs. the Phase 8 freeze.** Autogen-cheap but
  enlarges the frozen ABI. Accepted: `_lh` is the faithful no-spurious-
  alloc representation; the alternative (promote literal to a handle) is
  the degree-of-freedom loss backend §6.2 deliberately avoids.
- **Programmatic naming drift from the yaml convention.** Mitigation:
  per-symbol LIT FileCheck + link against the generated header; the
  convention is frozen at Phase 10.
