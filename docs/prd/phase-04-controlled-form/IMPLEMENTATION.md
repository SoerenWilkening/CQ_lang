# Phase 4 Implementation Plan — IR pass: controlled-form lowering

Companion to [`PRD.md`](PRD.md). The PRD fixes *what* and *why*; this
document fixes *how, in what order, and how each step is proven*. It is
grounded in the current tree (`taint-driven-pipeline` branch), verified
file-by-file against `ir-pass/`, `tools/`, `runtime/`, and `tests/e2e/`,
not just the PRD prose.

**Guiding constraints (from the request):**

1. **Modular** — one responsibility per translation unit; no module
   folded into another. Phase 3's seam (taint / rotation / opcode-driver
   / arith / compare / cast / measure / width-dispatch) is preserved; the
   new control work is **eight focused TUs**, not one `ControlledLowering`
   blob, so no file exceeds the budget.
2. **Test-driven** — every work package leads with the fixture that fails
   (RED), then the change that makes it pass (GREEN). Fixtures are
   first-class deliverables, authored before or with their code. Each WP
   leaves the suite green and `opt -verify` clean (green bisect).
3. **≤ 300 LOC per hand-authored TU** — budgets tracked in §3.
   `runtime/cq_templates.{h,c}` is autogenerated from
   `tools/opcode_table.yaml` and is **out of budget**.

## 0. The headline: `-O1` already dissolved most control; the surface and the pass do not exist

Verified against the tree, three facts reshape this phase versus a naive
reading "recover every `if`":

- **`-O1` folds most quantum control into Phase-3 flag-arithmetic before
  the pass sees it.** PRD §2.1's compiled menu is the spine: `if (q) y +=
  k` arrives as branchless `add y, zext(q-cmp)` and is *already correct*
  under the Phase-3 path. Phase 4 owns only what survives `-O1`: a tainted
  `select i1`, a `br`-diamond + `φ`, and the `&&`/`||` flag-select. The
  pass must **not** try to "recover" control `-O1` already folded (risk
  R1).
- **The controlled runtime surface does not exist yet.**
  `runtime/cq_templates.h` ships **780** generated decls, **zero**
  `_controlled`; the yaml grid is `{fwd,inv} × {qq,hl,lh}`
  (`tools/gen_templates.py:51` `VARIANT_INFO`). `runtime/cq_runtime.h`
  ships `cqrt_rz_<W>` (7) and a single `cqrt_toffoli(c1,c2,tgt)` — but no
  `cqrt_rz_<W>_controlled`, no `cqrt_toffoli_inv`. WP1 pulls this slice of
  Phase 8 forward, exactly as Phase 3 regenerated for `frem`/`_lh`.
- **The whole control mechanism is greenfield pass-side.** Today the
  *only* code that even looks at `SelectInst`/`BranchInst` is
  `isDataPositionCompare` (`CompareLowering.cpp:40`), which **excludes**
  branch/select-feeding compares from lowering and leaves them as raw
  `i1` "for Phase 4." Nothing detects regions, lowers a control flag,
  dissolves a `φ`, or linearizes a diamond. Phase 4 builds all of it.

So the load-bearing work splits cleanly: a **small, independent tooling
delta** (WP1, the controlled surface) that links before any pass change,
then the **greenfield control pipeline** (WP3–WP6) built on a thin
**infra layer** (WP2) that mirrors Phase 3's `TemplateName`/`WidthDispatch`
discipline.

## 1. The invariants that govern everything (state up front)

### 1.1 Handle typing & the flag-handle invariant (inherited from Phase 3 §1.1–1.2)

> A quantum register reference is always an `i32` handle; a comparison
> yields an `i32` flag handle (logically 1 qubit), never an `i1`.

Phase 4 adds no new typing rule — it *reuses* the Phase-3 flag-handle path
(`CompareLowering`), only **routing the flag to controlled ops** instead
of to a `zext`/measure (PRD §2.3). Every control flag is an `i32` handle.

### 1.2 One control wire per op (PRD §0)

Every controlled template/runtime symbol takes **exactly one** `i32`
control-flag handle, **prepended as argument 0**. There is no
doubly-controlled symbol. Multi-condition control (`&&`, `||`, nesting) is
built by combining flags into **one** fresh flag *upstream*
(`FlagConjunction`, §5.3), never by widening a signature. This is the
single most important shape constraint for WP1's signature generation and
for `ControlledSymbols`.

### 1.3 Tainted condition is necessary **and** sufficient (PRD §0)

A `select`/`br` whose `i1` condition is in `taint.Tainted` *is* a
controlled region. A classical-condition `select`/`br` has no physical
content and is left **byte-untouched** (a done-criterion + an explicit
fixture). Detection keys strictly on taint membership of the condition —
never on a source marker (there is none).

### 1.4 Lower-as-controlled — build the control-map before substitution (PRD §2.10)

The prototype's `cq-control` substituted `_controlled` *after* lowering
(it keyed off `cq_when` markers, having no taint analysis). The production
pass does better: **detect regions → build `value → controlling-flag`
map → emit the `_controlled` variant directly** when the in-shadow op is
lowered. One walk, no re-point. The merge `φ`/`select` (which has no
`cq_template_*` to attach `_controlled` to) is handled by the separate
dissolution step (§5.5), not by substitution.

### 1.5 The flag's lifecycle is bracketed *here*, LIFO (PRD §2.9)

The control flag is Phase 4's own region-scoped ancilla. Phase 4 emits
**both** its compute (compare → flag) and its uncompute (the compare
template's `_inv`), bracketing the controlled region, LIFO for nests. This
keeps the Phase 4 / Phase 5 seam clean: **Phase 5 owns *data*-handle
uncomputation; Phase 4 hands it a region whose *control* ancillas are
already balanced.** No `cqrt_free` here.

### 1.6 Collection-before-mutation & standing `verify` guard (Phase 3 §1.4–1.5)

The diamond-collapse and `φ`-dissolution mutate the CFG and RAUW across
types (`i1`/`i32`). As in Phase 3: **collect every site before mutating
any**, dissolve the `φ` *before* erasing the blocks that feed it (so no
use dangles, risk R6), and keep the second RUN line
(`… | %cq-opt -passes=verify -disable-output -`) on **every** fixture as
the guard for both handle-typing and the cross-type RAUW (verified clean
on this assertions-OFF LLVM-19; do not re-litigate). **No `br i32` is ever
created** (§1.1 gate).

### WP3 — Single-armed gate (`br`-diamond): the headline shape end-to-end

The first behavioral WP and the integration spine. A tainted `if (q > k) y
= gate(y);` arriving as a `br`-diamond + `φ[modified,original]` lowers to a
controlled rotation, the `φ` dissolves to the in-place handle, the diamond
linearizes, flag bracketed. Integrates `ControlDetection`, `ControlFlag`
(HL), `ControlledSubstitution`, `MergeDissolution` (`[mod,orig]` arm),
`CFGLinearization`, `ControlledLowering`.

- **RED.** `ir-pass/test/lowering_control_gate_br_i32.ll` (hand-authored
  from real `clang -O1` output of a single-armed quantum `if` with a gate
  body): tainted `icmp` → `br i1` diamond → `then: %ry = call cq_phi(%y,θ)`
  → `merge: %r = phi [%ry, then], [%y, entry]`. Against WP2 the diamond is
  untouched → RED.
- **GREEN.**
  - **`ControlDetection`** — `ControlPlan detectControlRegions(M, taint)`:
    for each tainted-condition `br i1`, recognize the 2-block diamond +
    merge `φ`; build a `ControlRegion{Condition, Kind=BranchRegion,
    Merge=φ, Shadow=[in-shadow ops], Pred, Arm, MergeBB, Depth=0}`; insert
    the arm's `cq_phi` into `plan.InShadow`. **Escape guard:** if an arm contains a
    `ReturnInst`/`measure`/`br` out of the region, emit the loud
    `DiagnosticInfoUnsupported` ("measurement/return under quantum
    control") and skip the region (PRD §5; structural cousin of the
    prototype's `computeFreePoint` ret check). Pure analysis — no IR
    mutation.
  - **`RotationLowering` edit** — at the mint, `HandleWidth[H] =
    abiWidthFromType(Op->getType())`; `if (plan.InShadow.count(phiCall))
    continue;` (skip — the orchestrator lowers it controlled). Factor the
    `cq_phi → cqrt_rz` emission into `emitRz(handle, angle, controlled,
    flag)`.
  - **`ControlFlag`** — `lowerControlFlag`: call
    `CompareLowering::lowerCompareToFlag(cond, wd, taint)` (HL path) to
    mint the `i32` flag; store `region.Flag`. The original `icmp` stays
    (consumed at linearization) so the `br i1` remains well-typed
    mid-pass (verify-clean WP boundary).
  - **`ControlledSubstitution`** — for each `region.Shadow` op, emit the
    controlled variant: gate body `cq_phi` →
    `csyms.controlledRotationFn(W)` → `cqrt_rz_<W>_controlled(flag, h, θ)`
    (via `emitRz(h, θ, /*controlled*/true, flag)`); record
    `taint.ControlFlag[result] = flag`.
  - **`MergeDissolution`** (`[mod,orig]` arm) — the merge `φ` has arms
    `[rotated_y, y]`: the controlled gate mutated `y` in place, so RAUW
    `%r → y` (the in-place handle) and erase the `φ`. Classify strictly by
    arm membership in `taint.Tainted` + `region.Shadow` (risk R2).
  - **`CFGLinearization`** — dissolve the `φ` **first** (done above), then
    erase the `br i1`, splice the arm block's (now controlled,
    unconditional) ops into the predecessor, merge to one block. `br i32`
    never created (§1.1). Erase the dead `icmp` last.
  - **`ControlledLowering`** — `lowerControlledRegions`: walk regions
    outer→inner; per region call ControlFlag → Substitution → Dissolution
    → Linearization; push the flag on the LIFO stack; after the region,

### WP4 — Classical-arm `select` reduction (const **and** runtime variable)

## 5. Module algorithms (the tricky bits, precise)

### 5.1 Detection & normalization to one shape (`ControlDetection`, PRD §2.2)

`-O1` chooses `select` vs `br`-diamond by arm cost, not canonically. Both
normalize to `ControlRegion`:

```cpp
struct ControlRegion {
  llvm::Value       *Condition;          // tainted i1 (cmp result / select cond)
  llvm::Value       *Flag = nullptr;     // i32 control flag (set by ControlFlag)
  enum { SelectRegion, BranchRegion } Kind;
  llvm::Instruction *Merge;              // SelectInst, or merge-block PHINode
  llvm::SmallVector<llvm::Instruction *, 4> Shadow;  // in-shadow gate bodies
  llvm::BasicBlock  *Pred=nullptr, *Arm=nullptr, *MergeBB=nullptr;  // br only
  unsigned           Depth = 0;
  llvm::Value       *ParentFlag = nullptr;  // nesting (PRD §2.7)
};
```

Detection is **pure analysis** (no mutation) so it can run before
`lowerRotations`. It returns a `ControlPlan` whose `InShadow` set names the
in-shadow `cq_phi` calls (so `lowerRotations` skips them) and whose
`Regions` carry the classified merge arms (drives §5.5). A `select i1` over `i1` flags (`…, i1 false` / `…, i1 true`) is a
**flag conjunction** (§5.3), not a data region. An arm that escapes
(`ret`/`measure`/out-of-region `br`) → loud diagnostic, region skipped.

### 5.2 Control-wire lowering, incl. Q+Q (`ControlFlag`, PRD §2.3–2.4)

Reuses the extracted `CompareLowering::lowerCompareToFlag(cmp, wd, taint,
qqWidth="")`:

- **HL** (q vs classical) — width from the classical operand, exactly
  Phase 3; predicate flip for literal-on-left; emit
  `cq_template_icmp_<pred>_<W>_hl(handle, classical) → i32`.
- **Q+Q** (`if (q1 < q2)`) — Phase 3 *bailed* here (laundered widths). Now
  `ControlFlag` reads `taint.HandleWidth[h1]` (recorded at the mint, §5.6),
  asserts `== HandleWidth[h2]`, and passes it as `qqWidth` so the helper
  emits the QQ template `cq_template_icmp_<pred>_<W>(h1, h2) → i32`.

The flag is recorded in `region.Flag`; the original compare is **not**
RAUW'd (it is erased by linearization/dissolution), keeping the IR
well-typed at the WP boundary.

### 5.3 Flag conjunction (`FlagConjunction`, PRD §2.5, §2.7)

One code path for `&&`, `||`, and nesting — "combine flags into a single
fresh flag":

| input | emit | uncompute (LIFO) |
|---|---|---|
| `fa && fb` | `f=alloc_i1(0); cqrt_toffoli(fa,fb,f)` | `cqrt_toffoli_inv(fa,fb,f)` |
| `fa \|\| fb` | De Morgan: `X(fa);X(fb);toffoli(fa,fb,f);X(f);X(fa);X(fb)` | inverse `X`s + `toffoli_inv` |
| nest(outer,inner) | `f_both=alloc_i1(0); cqrt_toffoli(outer,inner,f_both)` | `cqrt_toffoli_inv(...)` |

Every controlled op downstream is controlled by the **single** resulting
flag (§1.2). Depth-N nesting is depth-1 applied recursively + one
`cqrt_toffoli` per level.

### 5.4 Controlled substitution (`ControlledSubstitution`, PRD §2.10)

For each `region.Shadow` op, emit the `_controlled` variant with
`region.Flag` prepended, and record `taint.ControlFlag[result] = flag`:

- **gate body** `cq_phi(h, θ)` → `cqrt_rz_<W>_controlled(flag, h, θ)` via
  the shared `RotationLowering::emitRz(h, θ, /*controlled*/true, flag)`.
- **in-shadow data-arith/cast** (rare — `-O1` folds most to flag-arith,
  §6 R1): `OpcodeLowering` consults `taint.ControlFlag` and emits
  `controlledDataTemplateFn(...)`. Inert for the realized menu; the
  forward seam (§11 D2).

### 5.5 Merge dissolution (`MergeDissolution`, PRD §2.6)

The merge is a stock SSA merge (no `cq_template_*` to suffix), so it gets
its own dissolution keyed on **arm taint**:

- **`[modified, original]`** (`φ[rotated_y, y]`, the common `br` case) —
  the controlled gate mutated `y` in place; RAUW the merge to the in-place
  handle (`y`), emit no merge value.
- **`[classical, classical]`** (const or runtime variable) — `%d = A−B`
  (host `sub`, stays classical); `cqrt_alloc_<W>(B)`; one
  `cq_template_add_<W>_hl_controlled(flag, regB, %d)`; RAUW the merge to
  it. Variable arms reduce identically to constants (the `_hl` slot is a
  classical-operand slot).
- **`[≥1 tainted arm]`** — deferred to Phase 4.2 (PRD §5, beads
  `test_C_libtooling-mux`); detection currently rejects it (no region built)
  so nothing dissolves it — and, until the guard below lands, nothing
  *diagnoses* it either (silent passthrough; beads `…-mux-diag`).
  **It needs no new primitive** (correcting an earlier note): the HH
  `_controlled` adder minted by `controlledDataTemplateFn(stem, W,
  Shape::QQ, inv)` *is* the mux. One classical arm → `allocFn(C)` + register
  delta `Q−C` (uncontrolled `_hl`) + one `Shape::QQ` controlled add
  (`-mux.1`); both arms handles → `allocFn(0)` + two controlled adds
  `f·hp + ¬f·hq` with a `csyms.xFn()` ¬f bracket (`-mux.2`). Pass-side only:
  relax the `taint.Tainted.count(arm)` reject in `detectControlRegions` and
  add a tainted-arm branch to `dissolveSelect`.

Misclassification corrupts the result (risk R2): classify strictly by
membership in `taint.Tainted` + `region.Shadow`; one fixture per arm-taint
case.

### 5.6 The width side-table (`HandleWidth`, PRD §2.4)

Populated in `RotationLowering` at the alloc mint (line ~86): the classical
operand `Op` of the `cq_theta` carries the **logical** width, so
`HandleWidth[H] = abiWidthFromType(Op->getType())` records it on the
freshly minted `i32` handle before any RAUW launders it. `StringRef` keys
into `WidthDispatch`'s stable suffix storage. Staleness (a handle missing
from the table at a Q+Q compare) yields a wrong-width symbol → the
`ControlFlag` assertion + a per-width Q+Q fixture pin it (risk R3).

### 5.7 CFG linearization (`CFGLinearization`, PRD §2.11)

`br`-sourced only (`select` has no CFG to collapse). After substitution +
dissolution, the branch/arm blocks are dead. **Dissolve the `φ` first**
(so no use dangles), then erase the `br i1`, splice the arm's now-controlled
unconditional ops into the predecessor, and merge to a single block.
Collection-before-mutation (§1.6); `br i32` never created; per-fixture
`opt -verify` RUN line is the gate (risk R6).

## 11. Resolved decisions

All four resolved (2026-06-01); recorded here with the rationale so the
choice survives between sessions.

- **D1 — controlled-surface scope → FULL BINARY GRID. [DECIDED]** WP1
  generates `controlled` + `controlled_inv` across **all** binary ops
  (`qq`/`hl`/`lh`), mirroring the existing `fwd`/`inv` grid; the pass
  still only *emits* the subset it needs (`add_<W>_hl_controlled` for the
  §5.5 reduction; the runtime `cqrt_rz_<W>_controlled` / `cqrt_toffoli[_inv]`).
  **No controlled compares** — nesting combines flags via `cqrt_toffoli`,
  not controlled compares (PRD §2.7), so they would be dead symbols.
  Rationale: matches PRD §2.8 ("across the in-scope ops") + §6
  freeze-union; autogen is cheap (PRD §6 accepts the growth); doing the
  full binary grid once avoids a second yaml/regen/SHA churn against the
  frozen ABI at Phase 8. The `gen_templates_test.py` count literal is
  bumped to whatever the generator emits (authoritative), and the
  control-flag-arg-0 assertion covers the whole new grid.
- **D2 — `OpcodeLowering` control-map hook → WIRE IT. [DECIDED]** PRD §2.10
  mandates *"lowerOps emit the `_controlled` variant directly for in-shadow
  ops,"* so the `taint.ControlFlag` lookup is wired as a one-branch edit.
  In Phase 4's realized `-O1` menu it is **inert**: an in-shadow op is
  either a gate body (a rotation, owned by `RotationLowering` /
  `ControlledSubstitution`) or arith that produces a *new* tainted value —
  which makes the merge `φ` a `[tainted, …]` arm, the tainted-arm mux case
  (PRD §5; Phase 4.2 / beads `test_C_libtooling-mux` — pass-side, no new
  primitive). So: wire + document as the forward seam; **no fixture** for a
  shape `-O1` won't hand us; revisit if a future `-O` level preserves
  in-shadow data-arith.
- **D3 — module count → KEEP EIGHT TUs. [DECIDED]** Honors the request's

## 12. Phase 4.3 work packages — control-shape completeness (post-landing audit)

Phase 4 core (WP0–WP6) green-lit the happy paths, but the 2026-06-02 audit
(PRD §7) found **28 of 44** ordinary `if`-shapes crash or silently
miscompile, in **six root-cause families**. These WPs close the realized
`-O1` `if` menu. Each is small and independent except where noted; every
WP keeps `ir-pass-lit` green and every prior fixture byte-identical
(collection-before-mutation + standing `verify`, §1.6). RED fixtures are
hand-authored from **real `clang -O1` output** of the audit shapes, same
as WP3–WP6.

**Invariant for this phase:** *no shape may silently miscompile after a WP
lands.* Every change converts a crash/silent-miscompile into either a
correct lowering or a loud `DiagnosticInfoUnsupported`. WP9 (B1) and WP15
(D) are order-independent safety guards — pull either forward if a
"zero-silent-miscompile at every commit" bisection property is wanted.

### WP7 — Family A: multi-φ merge dissolution (the keystone)

A tainted diamond whose merge carries **≥2 φ** — ≥2 gated handles
(`if(q){u=g(u); v=g(v);}`), or a data assignment alongside a gate
(`if(q){y=5; u=g(u);}`) — leaks every φ past the first and crashes
(`PHI nodes not grouped`) or, by φ order, silently miscompiles. Single
biggest win: clears ~15 crashes + 2 silent miscompiles, and unblocks the
`goto` escape.

- **RED.** `lowering_control_multigate_i32.ll` (`br` diamond, arm with two
  `cq_phi` on distinct handles → 2 merge φ) and
  `lowering_control_mixed_arm_i32.ll` (arm with one `cq_phi` **and** a
  classical `y = 5` → a gate-handle φ + a classical-data φ). Both abort the
  pass today → RED.
- **GREEN.**
  - **`ControlPlan` / `ControlRegion`** — stop assuming one merge φ.
    `region.Merge = &MergeBB->front()` (`ControlDetection.cpp:407`, `:363`)
    becomes either a `SmallVector<PHINode*>` of all merge φ, or — simpler —
    keep `MergeBB` and have the dissolver iterate it (D4 carrier already
    holds `MergeBB`).
  - **`MergeDissolution::dissolveBranchPhi`** — iterate
    `for (PHINode &P : make_early_inc_range(MergeBB->phis()))`; for **each**
    φ take its `region.Pred`-edge incoming value (`getBasicBlockIndex(Pred)`)
    and RAUW→erase, exactly as the single-φ path. A `[mod,orig]` φ (gate
    handle) RAUWs to its in-place handle; a `[classical,classical]` φ that
    rode along in the same arm reduces via the existing §5.5 host-difference
    path (a mixed multi-φ merge dissolves each φ by its own arm-taint class).
  - **`CFGLinearization`** — unchanged: it already splices after dissolution;
    with all φ gone the `PHI nodes not grouped` abort cannot arise.
- **Files:** `MergeDissolution.cpp`, `ControlPlan.h`/`ControlDetection.cpp`
  (carrier), the two fixtures.
- **Done:** both fixtures green (every controlled gate emitted, all φ gone,
  one block, `verify`-clean); `compound-and-or` multi-handle + `goto`
  escape shapes from the audit now lower or diagnose; full lit green.

### WP8 — Family C: symmetric (two-content-arm) diamond

`if(q){u=g(u);} else {v=g(v);}` keeps a `br` diamond where **both**
successors hold content and fall through to a common merge — `matchDiamond`
(one-content-arm only) rejects it, `branchEscapes` deems it benign, and the
gates lower **uncontrolled** with a residual `br i1` on the handle. Silent
miscompile.

- **RED.** `lowering_control_ifelse_sym_i32.ll` (`br i1` → `A:{g(u)}`,
  `B:{g(v)}`, both `→ merge` with φ(s)). Today: residual `br`, uncontrolled
  gates → RED (negative check: no residual `br i1` on a handle).
- **GREEN.** `matchDiamond` (`ControlDetection.cpp:208-233`) gains the
  symmetric case: `Pred -[tainted br]-> {A, B}` where A and B are **both**
  single-pred blocks whose unconditional terminators target a **common**
  third block `Merge` carrying φ(s). Emit a region whose `Shadow` is the
  union of both arms' gates; the true arm's gates are controlled on `flag`,
  the false arm's on `¬flag` (the §2.5 `cqrt_x` LIFO bracket, reused). φ
  dissolution is WP7's multi-φ path. Composes with WP7 (a symmetric diamond
  with multi-handle arms is just more φ).
- **Files:** `ControlDetection.cpp` (matcher + region build),
  `ControlledSubstitution.cpp` (¬flag arm bracket), the fixture.
- **Done:** symmetric `if/else` lowers to controlled gates on both arms
  (flag / ¬flag), no residual `br`, `verify`-clean.

### WP9 — Family B1: angle-select diagnostic (diagnose-first)

`-O1` sinks `if(q){rz(u,a);}else{rz(u,b);}` into
`rz(u, select(cmp, a, b))` — a tainted-condition select over the
**classical `double` angle**. The SelectRegion gate (admits any non-`i1`
type) mis-lowers it as a data mux → type-mismatch crash. Diagnose first
(mirrors `-mux-diag`); WP10 lowers it.

- **RED.** `lowering_control_angle_select.ll` (`select i1 %c, double a,
  double b` feeding `cq_phi`'s angle arg) → currently crashes; becomes a
  **negative** fixture asserting the loud diagnostic.
- **GREEN.** In the SelectRegion admission gate (`ControlDetection.cpp:323`),
  alongside the `isIntegerTy(1)` exclusion, also exclude a select whose
  value type is **not an integer handle width** (`!Sel->getType()->isIntegerTy()`
  or `abiWidthFromType` empty) — a floating-point / parameter select is a
  rotation-angle choice, not a register mux. On that shape emit
  `diagnoseEscape`-style `DiagnosticInfoUnsupported`
  ("rotation angle under quantum control") and skip.
- **Files:** `ControlDetection.cpp`, the negative fixture.
- **Done:** angle-select diagnoses loudly instead of crashing; no data-mux
  symbol emitted for an fp select.

### WP10 — Family B2: angle-select → controlled-rotation-by-difference

Replace WP9's diagnostic with the correct lowering. `rz(u, cmp?a:b)` =
`Rz(b)` unconditional then `ctrl_cmp Rz(a−b)` — valid because Ry/Rz are
angle-additive (`Rz(b + f·(a−b)) = Rz(b)·ctrl_f Rz(a−b)`). Generalizes to
the N-way angle φ (the `-lowerswitch`/nested-mux angle case).

- **RED.** `lowering_control_angle_rotdiff.ll` (the WP9 shape) → now a
  **positive** fixture: expect `cqrt_rz_<W>(u, b)` + `cqrt_rz_<W>_controlled(flag, u, a−b)`.
- **GREEN.**
  - **Taint discipline** — exclude the angle operand (arg index 1) of
    `cq_theta`/`cq_phi` from taint propagation, so an angle-derived `select`
    is never marked a quantum-data value.
  - **A new angle-select reduction** (in `MergeDissolution` or a sibling):
    when a tainted-condition select feeds **only** rotation-angle operands,
    emit the unconditional base rotation `Rz(b)` and a controlled difference
    rotation `ctrl Rz(a−b)` on the flag (host `sub a−b` for constants;
    template `sub` for runtime). For an N-way angle φ, chain one controlled
    difference per distinct angle (LIFO-bracketed flags).
  - Lift the WP9 diagnostic for the lowerable case; keep it for any
    angle-select that is **not** a clean rotation-parameter feed.
- **Files:** `TaintPropagation.cpp` (angle-arg exclusion),
  `MergeDissolution.cpp`/new reduction, `RotationLowering.cpp` (emit base +
  controlled-difference), the fixture.
- **Done:** symmetric-by-angle `if/else` lowers to base + controlled-diff
  rotations; trace-equivalent to the braced controlled rotation;
  `verify`-clean.

- **Files:** `MergeDissolution.cpp`, the i64 fixture.
- **Done:** i64 mux emits i64 alloc/add; i32 mux fixtures byte-identical.

### WP12 — Family D: tainted-`switch` diagnostic guard (safety only)
