Binary under test: `cq-opt` `57e7420c50ddf8027d9c686672a1db282ed03d8bd94e5d9c366a8d2bfdc15439`
against the frozen ORACLE `0e280fc6…9c6d`. Produced by `corpus_E2.sh`; read with

## ⚠ The trailing `DONE` is MISSING, and the sweep is COMPLETE anyway — PROVEN, not assumed

`corpus_E2.sh` ends with `echo DONE >> "$OUT"`. That line never ran: the parent shell died with

```
corpus_E2.sh: line 58: syntax error near unexpected token `('
corpus_E2.sh: line 58: `ut copies — see the note on v() above)'
```

**Cause: the script was EDITED WHILE IT WAS RUNNING.** `bash` reads a script incrementally by byte
offset, so rewriting the file under a running interpreter makes it resume in the middle of a line.
The edit was a comment/`cut` widening applied to `msg()` mid-sweep. Two consequences, both recorded
rather than tidied away:

1. **The rows are unaffected.** Every row is written by the exported `row` function inside a
   `bash -c` child, and `export -f` copies the function into the child's environment — children do
   **not** re-read the script file. Only the parent's post-`xargs` trailer was lost.
2. **The `msg()` widening did NOT apply to this sweep.** Its rows still carry the 160-character
   truncation, which is why three movers' diagnostics appear as prefixes. That is closed by
   re-measurement, not by argument — see below.

**Completeness proof** (the reason the missing `DONE` is cosmetic):

```
$ { ls ir-pass/test/*.ll; find docs/prd/.../inc1-records \( -path '*/probes/*' -o -path '*_probes/*' \) \
      \( -name '*.c' -o -name '*.ll' \) ! -name '*.s1.ll' ! -name '*.ora.ll' ! -name '*.sub.ll' \
      ! -name '*.sora.ll' ! -name '*.ssub.ll' ! -name '*.s2.ll' ! -name '*.zero.ll'; } \
    | sed 's|^…/CQ_E2/||' | grep -vE '(_lib\.c|/lib[^/]*\.c)$' | sort > expected.txt
$ cut -d'|' -f1 corpus_57e7420c50ddf802.txt | sort > got.txt
expected=4986  got=4986  unique-got=4986
$ comm -23 expected.txt <(sort -u got.txt)     # in expected, never swept

$ comm -13 expected.txt <(sort -u got.txt)     # swept, not expected

```

Exact set equality, no duplicates, no omissions. The 31 excluded candidates are the `*_lib.c` /
`lib*.c` second TUs the recipe deliberately skips (they are linked into their `*_caller.c` rows).

**LESSON, for whoever copies this script next: never edit a shell script while it is running.** It
cost only a trailer here; it could as easily have corrupted the loop body. Make the edit in a copy,
or wait.
