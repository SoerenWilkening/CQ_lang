## F-YB-1 (P1, over-accept against an owner ruling) — `#pragma clang section` is not a "section" to the gate

bd **`test_C_libtooling-qce6`**.

`foldVolatileConstGlobalLoads` now skips `G.hasSection() || G.isAbsoluteSymbolRef() || !absolute_symbol`.
`#pragma clang section bss=/data=/rodata=/relro=` does **not** set the IR `section` field — clang attaches the
GLOBAL ATTRIBUTES `"bss-section"`/`"data-section"`/`"rodata-section"`/`"relro-section"`, which the backend
honours and `hasSection()` does not see. LLVM 19 has `GlobalVariable::hasImplicitSection()` for exactly this.

**The object really is in the named section** (`probes/aux/pr_nm.c`, `nm -m`):
`000000000000000c (__DATA,__mmio) non-external _K` — `probes/results/evidence/pr_nm.nm.txt`.

| probe | shape | SUBJECT | ORACLE |
|---|---|---|---|
| `s4_pragma_bss.c` | `#pragma clang section bss=…` · `static volatile int STATUS;` · `if (q > 3) r = STATUS;` | **ACCEPT exit 0, 2b clean** — `STATUS` baked as `cqrt_alloc_i32(0)` into the controlled copy (`evidence/s4_pragma_bss.SUBJ.s2.ll`) | DECLINE |
| `s4_attr_bss.c` | same, `__attribute__((section(…)))` | DECLINE | DECLINE |
| `s2_pragma_val.c` | data-section `K = 7`, `if (q > 3) r = K;` | **ACCEPT**, TRACE-IDENT with `r = 7` twin | DECLINE |
| `s1_pragma.c` | `if (q > 3) (void)K;` | **ACCEPT** (read deleted) | DECLINE |
| `i_dsect.ll` / `i_relro.ll` | IR attribute forms | fold (`cqrt_alloc_i32(7)`) | DECLINE |
| `s3_pragma_cls.c` | straight line `q = q + K` | folds, `cqrt_addc_i32(h, 7)` | **folds too** |

**INTRODUCED vs PRE-EXISTING.** The straight-line fold of a sectioned global is PRE-EXISTING (3c6m.14 Inc 3 —
the ORACLE has no section conjunct at all and folds `s3_pragma_cls` and `s3_attr_cls` alike). The
quantum-branch population (`s1`/`s2`/`s4`) is INTRODUCED by vsfp: the ORACLE declines it, round 3's arm fold
(bd `stl3`) made it accept, and round 4's conjunct closes only the attribute spelling. **Round 4's claims are
falsified**: `QramLowering.h` "Every conjunct is a gate here"; TRACK_VSFP §R4.6 "refuses a named section";
the fixture headers' "non-section object". The implementer's own §R4.11 item 6 named this spelling as the
first thing to attack.

Why P1 and not P2: the ruling lists section globals among the shapes that "keep their loud declines"; the
accepted program is verify-clean, 2b-clean and exit 0, and when the object is a device register the circuit
carries the INITIALIZER instead of the read (s4: an MMIO status read under quantum control becomes the
constant 0). A silent wrong value, not an over-decline.

**Fix direction (NOT built, NOT measured):** add `G.hasImplicitSection()` to the gate. It over-approximates —
a `bss-section` attribute on a data-kind global is not actually placed by the backend — which is the safe
direction. Pin with a pragma decline fixture for BOTH `bss` (zero-init, the MMIO-register idiom) and `data`,
mirroring `lowering_reject_volatile_global_section.ll`.

**What held in the section conjunct** (all declined on SUBJECT, as the ruling requires):
`__attribute__((section))` at file scope and on a function-local `static` (`s0_attr`, `s7_localsec`), MS
`#pragma data_seg` (emits a real `section`, checked by hand), `__attribute__((used))` and `retain`
(`@llvm.used` ConstantArray user forfeits), `_Thread_local` (`@llvm.threadlocal.address` call user
forfeits), `GlobalAlias` onto `K` (`i_alias.ll`), `!absolute_symbol` as a RANGE and as full-set
(`i_absrange`, `i_absfull` — `isAbsoluteSymbolRef()` is true for any node), `externally_initialized`
(`i_extinit`), a write under quantum control (`s5_write`), an external global (`s6_ext`). Folds that the

## F-YB-2 (P3, falsified rationale — L7 shape) — SimplifyCFG does NOT go through the folder

builds: through the folder, so `select %c, i1 true, i1 false` IS `%c`"*. Measured

`%spec.select = select i1 %c, i1 true, i1 false` — SimplifyCFG uses `IRBuilder<NoFolder>`; the `-O1` twin

The code is sound and the conclusion holds (the twin does end with `%c`). Soundness argued from
`simplifySelectInst`'s contract and not contradicted by any probe: it returns a constant or one of

`undef`/`poison` literal unless the CONDITION is a `poison` constant (a `br i1 poison` — UB, not reachable
from `-O1` C). Graded P3 because nothing depends on the false ground, but it hides the real parity bar
(SimplifyCFG **+ InstCombine**, which does strictly more): `x1.c` (`int p = 0; if (q > 3) p = KI;`) accepts
with a 4.4 copy merge while its twin emits `cq_template_zext_i1_to_i32` — same unitary, different stream
