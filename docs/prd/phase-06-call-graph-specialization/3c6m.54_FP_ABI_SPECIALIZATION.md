# Issue 3c6m.54 — libm fp-ABI specialization (fp quantum arg/return in a Phase-6 clone)

`test_C_libtooling-3c6m.54` (parent epic `3c6m` math.h demonstrator; discovered
from the `3c6m.51` ld80 −O1 re-census). Branch: `3c6m.14-control-l6`.

## The problem

Phase-6 specialization clones a pure-classical callee, seeds its tainted params,
lowers the body under a disjoint `cloneTaint`, and Bennett-wraps it
(compute → copy-out → uncompute → free). Until now the accept gate required every
**tainted argument** to be an `i32` handle and the **return** to be exactly `i32`
(`SpecializeReject.cpp` — the `FpAbi` reject). A real libm reduction like
`long double coshl(long double)` therefore declined char-for-char on
`"cq specialization: floating-point quantum argument or return has no reversible
copy"`.

The 2026-07-16 ld80 −O1 re-census surfaced this as the single highest-leverage
capability: **7 ld80 cells** (`atan2l coshl lgammal log10l powl sinhl tgammal`)
plus their f32/f64 siblings all decline on this one gate, even though the runtime
`cqrt_copy_f{16,32,64,80}` (+ `_controlled`, bd 38t2 / kjd1) **already exist**.
The gate was a largely-unwired fence, not a physics wall (3c6m.50 found zero
C-physics walls on these cells).

## The ABI insight — a quantum value is ALWAYS an i32 handle (Rule 15)

A tainted value lowers to an `i32` runtime handle regardless of its source LLVM
width. For an INTEGER clone this is invisible: an `int helper(int)` body is
already all-`i32`, so the verbatim clone's `i32` param doubles as the handle and
every `cq_template_*_i32` reads it directly. For an FP clone the source type is
`x86_fp80`/`double`/… but the handle is still `i32`, so the clone's **signature**
must be rewritten: each tainted-fp param → `i32`, and a tainted-fp return → `i32`
(the copy-out handle). The transient type mismatch at the call site is laundered
exactly like the theta RAUW-to-handle (RotationLowering §1): `specialize` runs
BEFORE `lowerRotations`/`lowerOps`, so the caller's fp arg (a `cq_theta_f80`
result, still fp-typed at retarget) becomes the `i32` handle when the theta lowers,
and the caller's `cq_measure_f80(%r)` consumes the clone's `i32` result directly
(`cqrt_measure_f80` takes an `i32` handle).

## What ships

1. **`abiWidthHasReversibleFpCopy(w)`** (`OpcodeSupport`) — the fp set
   `{f16,f32,f64,f80}` that has an **uncontrolled** `cqrt_copy_f<W>` (runtime
   `cq_runtime.h:285-288`, bd 38t2). Mirrors `abiWidthHasControlledFpCopy` /
   `widthHasQramCell`; deliberately **NOT** `widthHasReversibleCopy` (whose fp
   null IS the live f64-angle classifier for the select/switch/loop data-mux
   paths — must not move). `f128`/unknown/integer widths are false.

2. **Gate lift** (`SpecializeReject.cpp`, the single authoritative
   `classifyCandidate` — Rule 14):
   - **Arg gate (A):** a tainted arg is admitted iff it is an `i32` handle OR an
     `abiWidthHasReversibleFpCopy` fp width. A tainted `i16`/`i64`/`i128` arg
     still declines `FpAbi` (out of scope — only fp is lifted here).
   - **Return gate (scanBody §2):** a return is admitted iff it is `i32` (int,
     via `wd.copyFn`) OR an `abiWidthHasReversibleFpCopy` fp width. `i128`/`i64`
     returns and `f128` still decline `FpAbi`.

3. **Clone signature rewrite** (`SpecializeClone.cpp` `cloneFor`): when the
   target signature differs from the callee's, build the clone via
   `Function::Create` + `CloneFunctionInto` with a cross-type arg VMap
   (tainted-fp params → `i32`; the fp-tainted return → `i32`). The verbatim
   `CloneFunction` path is preserved byte-for-byte for the no-rewrite (integer)
   case, so every existing integer spec fixture is untouched. Param attributes on
   a rewritten (fp→i32) slot are stripped (an fp-typed attr is invalid on i32).
   The **return** rewrite decision uses `predictReturnTainted(Callee, Mask)` — a
   pure forward-taint closure on the single-block callee (mirrors `seedClone`).
   This is a sound **over-approximation**: predicted-classical ⟹ truly classical
   (the inner-call scrub only REMOVES taint), so a genuinely-classical fp return
   is never rewritten to `i32` (it stays fp and is returned verbatim).

4. **Mispredict guard** (`Specialization.cpp` `buildClone`): the only prediction
   gap is predicted-tainted-fp-return but the post-drain
   `ReturnTainted == false` (an inner tainted-arg clone returned classical and the
   final return depended solely on it — unreachable in the always-inlined census
   cells, which have no inner calls). Then the clone declares `i32` return but the
   return value is a classical fp — a broken module. This is caught with a **loud
   source-located decline** BEFORE `emitBennettWrap`, never a silent miscompile
   (and, absent the guard, LLVM's own verifier would reject it — never verify-clean).

5. **Bennett copy-out over `cqrt_copy_f<W>`** (`BennettWrap.cpp`): the copy width
   is the **original** fp width (`abiWidthFromType(Callee->getReturnType())`, e.g.
   `f80`), NOT the clone's rewritten `i32` return type. The out rail is
   `cqrt_alloc_f80(fp80 0.0)` (an `i32` handle), the copy is `cqrt_copy_f80(result,
   out)`, and the clone returns the `i32` `out`. `WidthDispatch::copyFnClone`
   mints `cqrt_copy_<W>` for the spec return set `{i32} ∪ {f16,f32,f64,f80}`;
   `allocFn` already admits fp. The forward fp templates
   (`cq_template_fmul_f80_hl` …) reverse through the width-agnostic generic
   `cq_template_*_unc` branch of `EmitInverse` (no change there).

## The ANGLE-SAFETY fence (Rule 3 — the f64/angle miscompile family)

This is the Rule-13-critical boundary. Lifting the return gate **relaxes the
kmdc R1 precondition** (`RetW == "i32"`), which `kmdc_FP_SELECT_IN_CLONE.md`
named load-bearing. It stays safe on two independent pillars, both pre-existing:

- **Inside the clone the angle hazard is structurally absent.** `scanBody`
  rejects every `cq_theta`/`cq_phi` as `QuantumPrimitive`, and `buildClone` never
  lowers rotations, so a clone body has **zero** rotation arg-1 angle slots. An fp
  arg/return can never reach an angle *inside* the callee — the three-legged fence
  is vacuous here (verified: a clone body with a `cq_phi` on the fp param declines
  `QuantumPrimitive`, not `FpAbi`; fixture `spec_reject_fp_arg_used_as_angle.ll`).

- **The fp return becomes an i32 handle, and the top-level angle fence backstops
  it.** Under the lifted gate an fp-tainted return is **copied out to an `i32`
  handle** (never a raw fp value crossing the boundary). `specialize` marks that
  result tainted; if the caller steers it into a rotation arg-1 angle,
  `declineTaintedAngle` (RotationLowering, straight-line) / `taintedAngleGate`
  (ArmClassify, region) fires — exactly the residual kmdc already anticipated
  ("even the returned i32 … is caught by taintedAngleGate"). So the kmdc R1 gate
  is **superseded**, not merely removed: its job (keep fp off a caller angle) is
  done by the copy-out + the angle fence. Fixture:
  `spec_reject_fp_return_used_as_angle.ll`.

**Load-bearing preconditions (re-review triggers):** (R2, unchanged) `scanBody`
keeps rejecting `cq_theta`/`cq_phi`; (R-new) `declineTaintedAngle` /
`taintedAngleGate` keep declining a tainted rotation arg-1 — they are now the SOLE
fence for fp escaping toward a caller angle. `isLiftableFpSelect`'s `{f32,f64}`
select-copy whitelist (kmdc R3) is independent of this ABI change and is left
untouched.

## Rule-13 clearance

Two independent reviewers (fp-copy/Bennett-reverse correctness lens + the
angle-boundary/over-accept lens) — the f64-angle miscompile family.

**Reviewer B (angle-boundary / over-accept): CLEAN.** 12 angle-bypass probes
(clone fp result → caller angle, via fp-op / cast round-trip / a second clone /
`freeze` / a tainted-control diamond arm / classical-cond `select`+`phi` / arg-0
AND arg-1 aliasing / the kmdc fp-select clone) ALL decline loudly
(`declineTaintedAngle` / `taintedAngleGate` / `declineFrozenWire` /
`declineClassicalMuxes`). The width boundary is EXACTLY {f16,f32,f64,f80}
(fp128/ppc_fp128/bfloat/`<2 x double>`/i16/i64/i128 all decline). The mispredict
guard is sound (predict-classical ⟹ truly-classical). No silent miscompile.

**Reviewer A (fp-copy / mechanics): found + fixed a CONFIRMED defect.** The
`retargetSite` call-rebuild (fresh i32-returning `CallInst` + cross-type RAUW) fired
for an INNER call inside another clone (TRANSITIVE fp specialization, and the
intra-clone fp cache-hit), but the rebuilt value was never re-registered into the
outer `cloneTaint` — so `ArithLowering` read the inner result as UNTAINTED and put
the i32 handle in an fp LITERAL slot → a BROKEN MODULE (`opt` verifier abort, a
Rule-1 violation + latent silent-miscompile generator). **FIX:** the drain loop now
migrates the rebuilt inner result's taint (`Tainted` + `BirthOrder` + `HandleWidth`)
onto the new `CallInst` (mirroring the module-level re-seed `specialize` does for a
top-level rebuilt result), and the top-level result `HandleWidth` moved from
`buildClone` to `specialize` so the cache-hit path is covered too. This ENABLES
transitive fp specialization correctly (the fp analog of the shipped integer 6.3
path): reviewer probes P6 (Q+C transitive), P14 (Q+Q transitive), P11 (direct-return
transitive), P13 (cache-hit + result cast) all now COMPILE + verify-clean with
correct operand order and the inner void twin `@__cq_q_<inner>_<mask>_unc` reversing
in LIFO. Pinned by `spec_accept_fp_transitive.ll`. Re-verified: full suite green.

**Net verdict: CLEAN after the fix** — no verify-clean silent miscompile and no
broken-module abort on any accepted shape.
