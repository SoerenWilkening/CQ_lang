# bd 3c6m.14.2 — the shielded-cone definedness proof: the decision, in writing

**Status:** SHIPPED, branch `3c6m.14-control-l6`, 2026-08-08.
**Scope:** `ir-pass/src/PredMuxFlatten.cpp` only. No frozen symbol, no YAML edit,
no new runtime template, no new gate sequence.

**Decision: direction (b), narrowed — the shielded-cone CALL admission is
deleted for arbitrary callees and kept only for the project's own curated
intrinsic set.** This is the opposite of what the ticket expected, and it
**reverses an ACCEPT surface bd 3c6m.14.1 shipped and Rule-13-cleared one session
earlier**. The measurement the ticket asked for is what turned it, and an
adversarial round then confirmed it. Both are recorded below; §4 is the part to
read if you only read one section.

---

## 0. What the proof is for

`clang -O1` lowers `a && b` to the poison-shielded form
`select i1 %a, i1 %b, i1 false`, which never observes `%b` when `%a` is false.
PredMux's flatten canonicalizes that to a plain `and`, which **does** observe it.
`coneDefinedAfterFlagDrop` is the claim-time proof that licenses the rewrite.

---

## 1. The defect

The CallInst clause admitted any callee passing `isSpeculatablePureCalleeBody`.
That proof answers **pure + total + terminating**, which is not **returns a
defined value**, and it fails to be a definedness proof in two independent ways:

* it reaches its verdict through `isSpeculatableDataflow`, which admits a
  variable-amount `shl/lshr/ashr` and `fptosi/fptoui` **unconditionally** — the
  very ops the shielded-cone whitelist deliberately FAILS inline, because their
  poison is inherent and `stripPoisonCone` walks only `I->operands()` and so
  never enters a callee body;
* it **skips terminators**, so a body whose only instruction is a terminator
  passes **vacuously** — nothing about the returned value is examined.

---

## 2. The exhibits — this was never an unproven exploit

Both on the **pre-fix** plugin (`be3e8705d5a03396…`), both `opt` exit 0, both
`opt -verify` clean, both `free_pairing_check.py` **STRICT: 6/6 verified, 0
violations**. Every gate green, wrong unitary.

### E1 — a Bennett clone returning literal poison as a qubit handle

`define i32 @leaf(i32 %a) { ret i32 poison }` passes the purity proof vacuously.
Emitted: `define internal i32 @__cq_q_leaf_1(i32 %a) { ret i32 poison }` — a
clone that allocates no rail, frees no rail, and hands back **poison as an `i32`
qubit handle**, which the caller feeds to `cq_template_icmp_sgt_i32_hl`, to that
compare's `_unc` adjoint, and to a `cqrt_free`. Linked and run at the shipped
**-O0** stage 3 the handle materialised as `h0`, the `%q` rail itself:

```
cq_template_icmp_sgt_i32_hl(h0, 3) -> h3
cq_template_icmp_sgt_i32_hl(h0, 0) -> h4        <-- must have been leaf(q)'s rail
```

The circuit computes `(q>3) ∧ (q>0)` instead of `(q>3) ∧ (leaf(q)>0)`.

### E2 — a poison **constant leaf**, with no call at all

The old walk shortcut every non-`Instruction` with a bare
`// Constant / Argument leaf — defined`. A literal `undef`/`poison` **is** a
Constant, so `%r = add i32 %q, poison` emitted
`call i32 @cq_template_add_i32_hl(i32 %h, i32 poison)`, which at stage 3 became
`cq_template_add_i32_hl(h0, 73896)`.

E2 matters beyond its own arm: it falsifies the natural defence of the call
clause — *"tainted args ⇒ Phase-6 clone ⇒ runtime templates, so no IR poison can
survive"*. Here the poison survives as a template **operand**.

### E3 — found by the Rule-13 round, **on this ticket's own first fix**

A curated `ctlz(0, i1 true)` in a shielded cone. Direction (a) — a definedness
proof over the callee body, written first exactly as the ticket proposed — still
**accepted** it: `opt` exit 0, verify clean, free-pairing STRICT 6/6, and the
linked trace fires `cq_template_icmp_sgt_i32_hl(h32, 0)` — a gate on rail `h32`,
an index `cqrt_alloc_*` never returned, with its `_unc` naming the same phantom.

The poison rides an **immarg**: an operand, not an annotation.
`hasPoisonGeneratingAnnotations()` cannot see it, no `drop*` API can strip it,
and it is a `ConstantInt` so `valueCarriesUndef` cannot see it either. Every
mechanism the file has for neutralising poison structurally misses it.

### What is NOT exhibitable, stated precisely

The `shl i32 %a, %a` and `fptosi` callees — the ticket's headline face — accept
on the pre-fix plugin but are **laundered by the emitter**: the poison-bearing op
becomes `cq_template_shl_i32`, a total function of two handles, and the
conjunction is `cqrt_toffoli` where `0 ∧ garbage = 0`. On those shapes the
claimed safety is real — as an **emitter property the proof neither states nor
checks**, with E1/E2/E3 as three inputs for which it does not hold.

|---|---|---|
| 949 pre-existing ir-pass fixtures | **1** (`control_predmux_accept_i80_cmp_purecallee_conedef.ll`, now renamed `..._reject_...`), `curated=0 pure=1 DECIDING=1` | real; it is the whole measured surface |
| 238 registered e2e slices (stage-1 IR; 238/238 compiled, **0 skipped**) | **0** | **NONE — declared** |
| 248 real openlibm TUs at `-O1` | 39 poison-shielded select-forms; **5** carry a call in the shielded cone; **all 5 curated intrinsics, 0 pure-callee** | shape census only — see two caveats |

**Caveat 1 on the openlibm layer, raised by the Rule-13 judge and correct:**
`grep -l cq_theta olm/*.ll` returns **0 of 248**. No openlibm TU carries a taint
source, so the shipped pass takes its passthrough early-out on every one and
never runs a cone proof there. That census measures **which shapes `clang -O1`
emits from libm C** — the right question for "what would a call in a shielded
cone look like in real code" — and **nothing** about fence reach. It is quoted
here only for the former.

**Caveat 2 — the first run of this census silently scanned 238 modules, not 248,
and a round-two lens caught it.** The compile loop wrote `<basename>.ll`, and
openlibm has **10 basenames that collide between `src/` and `ld80/`**
(`e_fmodl`, `e_hypotl`, `s_ceill`, `s_floorl`, `s_modfl`, `s_nextafterl`,
`s_nexttoward`, `s_nexttowardf`, `s_remquol`, `s_truncl`), so the `ld80` body
overwrote the `src` one and 10 modules were never scanned. The figures above are
from the **re-run with `<dir>-<basename>.ll`**: 248 distinct modules, **39**
shielded select-forms (the first run reported 35). The conclusion is unchanged —
5 call-bearing cones, all curated, 0 pure-callee — but the first number was
wrong, and *"248 compiles succeeded"* is not *"248 modules were scanned"*. Count
what is on disk, not what the loop counted.

## 4. THE DECISION, and why it reversed

The ticket offered **(a)** a definedness mode mirroring the stricter whitelist,
or **(b)** drop the CallInst clause and accept the over-decline, warning that
"(b) is safe but will kill real adia Lever C accepts (the plain -O1 expl→floorl
shape)", and instructing: measure which fixtures and slices depend on the clause
**before** choosing.

**Finding 1 — the ticket's case against (b) rests on a conflation.** The
coshl→expl / expl→floorl pure-callee accept is pinned by
`lowering_predmux_speccall_flatten.ll` at **S1**, `recoverRegion`'s E4 call
admission, where the call sits in an **arm**. `coneDefinedAfterFlagDrop` never
sees it. It still passes, along with `lowering_fp80_union_seed_purecall_i80cmp.ll`
and the multi-TU e2e slice `e2e-predmux-purecallee-i80cmp`. Nothing (b) does
touches that shape.

**Finding 2 — direction (a) was built first, and its Rule-13 round found a fresh
verify-clean silent miscompile inside it** (E3 above), plus an unsound
`getZExtValue` shift-width check that admitted `shl i128 %w, 1<<100` because the
low word is zero. Two real defects in ~40 lines of new proof **serving zero
measured inputs**. The round's judge returned **NOT CLEARED** and recommended (b)
independently.

**Finding 3 — Rule 17 does not protect this surface.** Rule 17 says a decline is
not the development escape hatch for *the shape we set out to build*. Nobody set
out to build "an arbitrary pure callee inside a poison-shielded `&&`". bd
3c6m.14.1's own close note records S4 as a surface that "was enumerated
NOWHERE" — an incidental consequence of widening a **speculation** clause into a
context carrying the strictly stronger **definedness** obligation. The Prime
Directive governs instead: an unproven, unpopulated accept surface should not
exist.

**What shipped, therefore:** the clause admits only the curated set, whose
totality is a fact about code the project ships rather than an inference about
user code, and which is the only call shape with any measured population.

### The measured cost, stated as a number

Of 16 purpose-built probes whose callee bodies are **provably total by
construction**, **14 now decline** — the entire pure-callee accept surface. The 2
that still accept are the inline shapes that never went through a call.
`D13_curated` (a callee whose body calls `llvm.fabs`) is among the 14: a curated
intrinsic **inline** in a cone still accepts, but wrapping it in a user function
does not. That is the price, it is an over-decline, and it is safe.

## 5. What shipped

1. **The pure-callee disjunct is deleted** from `coneDefinedAfterFlagDrop`'s
   CallInst clause. The clause is now
   `isCuratedReversibleIntrinsic && doesNotAccessMemory && !curatedIntrinsicCanBePoison`.
2. **`curatedIntrinsicCanBePoison`** — refuses `llvm.ctlz`/`llvm.cttz` with
   `is_zero_poison` and `llvm.abs` with `is_int_min_poison`, and refuses
   conservatively when the immarg is not a `ConstantInt`. Every other member of
   the curated set is genuinely total (`bswap`/`bitreverse`/`ctpop`,
   `smin`/`smax`/`umin`/`umax`, the four `*_sat`, `fshl`/`fshr` — the rotate
   amount is modulo the width — and the p119 hardware fp survivors, where NaN is
   not poison). **That list is coupled to `intrinsicStem` in
   `IntrinsicLowering.cpp` with nothing mechanical holding them together; re-read
   it when either moves.**
3. **`valueCarriesUndef`** at the cone walk's leaf, descending constant
   aggregates/expressions with a **visited set and no depth budget** (a cut-off
   inside a yes/no predicate makes the answer depend on the cut-off — bd
   `budget-in-a-memo-and-probes-with-no-power-2026-08-08`).
4. **`definedOpAfterFlagDrop`** — the per-instruction whitelist, extracted and
   named, with the shift-amount range check respelled `APInt::ult` instead of
   `getZExtValue() <`. In a **Release** plugin the `getZExtValue` assert is
   compiled out and it returns the low word, so `shl i128 %w, 1<<100` read as an
   amount of 0 and was admitted while the same shift by 200 declined.

### Tried and REVERTED, deliberately

`stripPoisonCone` → `dropPoisonGeneratingAnnotations()` (adding LLVM 19's third
family, call **return attributes**). Under the narrowed clause no admitted call
can carry a return attribute into emission — a tainted curated intrinsic is
replaced by its `cq_template_*`, a classical one declines downstream — so the
wider drop has **no soundness role**, while that walk provably **exceeds** the
proof's walk (it recurses past the `cq_theta`/`cq_phi` leaf into the classical
seed subtree and mutates instructions the whitelist refuses). Widening the DROP
without first narrowing the WALK makes a known over-reach worse. Both halves are
filed together; **fix the walk first.**

## 6. Evidence

**Probe family, reach-gated** (a probe counts only if the **pre-fix** plugin
accepts it; otherwise it never reached the clause and is reported NO-REACH, never
as a pass): **REACH 37/38**. The one NO-REACH is `D07_freeze`, which both plugins
decline identically at a pre-existing Phase-6 gate. **21/21 poison probes
decline; 0 still accept.**

**Arm-kill, 6/6 pinned.** Each arm deleted individually turns its designated
fixture RED, each mutant built with an mtime bump and a `.so`-hash assertion
against the shipped plugin (cmake silently skips a same-second rebuild). B2's
mutant — putting the deleted disjunct back — **fails to compile** without also
restoring the forward declaration, which is independent evidence the declaration
removal was right. B6 is the over-tightening control: dropping the curated
disjunct too (the ticket's *literal* (b)) turns `..._curated_total.ll` red.

**Verdict diff, pre-fix vs shipped:** of the 949 pre-existing ir-pass fixtures,
**exactly 1 moved** — the S4 accept, as intended. **0 of 238** e2e slice stage-1
modules moved.

**Gates.** `ir-pass-lit` 957 = 956 pass + 1 XFAIL. Full `ctest` 249/249
uncontended. No YAML touched, so `gen_templates.py --check` is unaffected.

## 7. What this does NOT establish, and what is filed

* `valueCarriesUndef` tests for a **contained** `UndefValue`, so a constant
  expression that **generates** poison without containing one (an out-of-bounds
  `ptrtoint (ptr getelementptr inbounds (...) to i64)`) still reads as a defined
  leaf. **Pre-existing and identical on both plugins.** The Rule-13 round's
  headline evidence for it — a trace differing between two runs of the same
  binary — was refuted: that is ASLR of a relocated global address, reproducible
  with a provably-**defined** `ptrtoint (ptr @g to i64)` and with PredMux absent
  from the module entirely. Filed.
* `stripPoisonCone`'s walk exceeds the proof's walk, and drops 2 of LLVM 19's 3
  annotation families. Both pre-existing. Filed together — **narrow the walk
  first**.
* Callee **declaration**-level and **parameter**-level attributes are invisible
  to the proof and to the strip. Pre-existing, BASE-identical, and neutralised
  downstream by `SpecializeClone.cpp`'s `removeRetAttr(Attribute::Range)`. Filed.
* A callee returning `ret i32 poison` with **no** select and **no** branch is
  still accepted — that is Phase-6 specialization, a different surface. Filed.
* `fneg` and `LoadInst`/`GEP` are refused by `definedOpAfterFlagDrop` though
  `fneg` is total. Over-declines, safe, unchanged from the pre-fix inline
  behaviour. Not filed as defects.
* The consumer census unit is now stated explicitly in the source: **three
  textual call sites plus one recursion**, with S1/S2 the same site counted twice
  because its answer is context-sensitive. bd 3c6m.61's comment and bd memory
  both said THREE and both were wrong; re-derive by grep over all of `ir-pass/`,
  never inherit the number.
