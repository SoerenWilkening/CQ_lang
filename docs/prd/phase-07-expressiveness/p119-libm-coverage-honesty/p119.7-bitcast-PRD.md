# PRD — p119.7: lower tainted fp↔int `bitcast` (the `EXTRACT_WORDS`/`INSERT_WORDS` masked blocker)

> Sub-task of epic `p119`. Owner-directed 2026-07-06 (after the Phase-1 blocker
> audit). Backend correctness stays deferred (owner, 2026-06-10); this is a
> lowering-surface change (a new reversible cast template family).

## Problem

The Phase-1 injection audit (`[[p119-phase1-blocker-audit]]`,
`[[p119-phase1-bitcast-masked-blocker]]`) found that a tainted **`bitcast
double↔i64`** — the `EXTRACT_WORDS` / `INSERT_WORDS` / `GET_HIGH_WORD` idiom that
opens **nearly every** injected openlibm body — is **not lowered**:

- `castInScope` (`OpcodeSupport.cpp`) has no `bitcast` branch → falls to
  `return false`.
- `foldIdentityBitcasts` (`TaintPropagation.cpp`) folds only same-width
  **int↔int** bitcasts.
- Result: `no template for opcode 'bitcast i64' in tainted context`
  (verified directly: `theta_f64 → bitcast f64→i64 → xor → bitcast i64→f64 →
  measure_f64`).

It is the corpus-wide **#1 blocker by frequency**, but **reclassify-only**: every
census function trips an earlier-stage blocker first, so lowering bitcast alone
compiles **zero** functions. It is nonetheless a genuine **prerequisite** for the
Phase-2 branchless-injection path (branchless soft-float bodies also open with
`EXTRACT_WORDS`).

## Why it was declined (and why lifting it is safe)

The `iw81.1` fixtures (`lowering_reject_bitcast_{fp_to_int,int_to_fp}.ll`)
declined fp↔int bitcast on the **f64-as-angle fence** (Rule 3): an `int→fp`
bitcast could yield a tainted `double` that reaches a rotation's **arg-1 angle**
slot — a silent-miscompile family.

That hazard is **already caught by the authoritative angle guard**
`declineTaintedAngle` (straight-line) / `taintedAngleGate` (control regions),
which fire whenever a rotation's arg-1 operand is **tainted** — and which run in
**`lowerRotations`, BEFORE `lowerOps`** (where casts, incl. bitcast, are
lowered). Taint already propagates through bitcast (that is how the census
reaches deep openlibm lines). **Verified empirically:** a `sitofp`-produced
tainted angle (the same CastLowering path bitcast uses) declines
`unsupported quantum-derived rotation angle`. So the bitcast decline was
**redundant belt-and-suspenders**; the actual fence is the angle guard, and it
stays.

**Semantics.** A tainted `bitcast double↔i64` on data `q = Σαᵢ|dᵢ⟩` reinterprets
the *same* basis states under a new type label — amplitudes and basis unchanged.
It is a reversible **identity relabel**, zero gate, self-inverse. It only ever
fires on *tainted data* (an angle is classical/untainted); downstream
reversibility of `and`/`shl`/… is existing machinery, unchanged. It is exactly a
new cross-domain cast, parallel to the shipped `sitofp`/`fptosi`.

## Scope

Lower a tainted **same-bit-width fp↔int `bitcast`** as a new reversible cast
template family, **both directions**:

| from→to | pairs |
|---|---|
| fp→int (`EXTRACT_WORDS`) | f16→i16, f32→i32, f64→i64 |
| int→fp (`INSERT_WORDS`) | i16→f16, i32→f32, i64→f64 |

- **`f80↔i80` is EXCLUDED** — `intBits` has no `i80`, so `castInScope` never
  admits it and the width capture returns `""` → declines (Prime Directive; long
  double `EXTRACT_WORDS` uses a union, not a bitcast).
- **Vector / aggregate / `i128↔fp` / `f128` bitcasts DECLINE** (empty captured
  width → `diagnoseNoTemplate`).
- **Same-width int↔int** stays the existing pre-lowering **fold** (untouched).

## Implementation (width-only ABI, Rule 15)

1. `tools/opcode_table.yaml`: add a `bitcast` opcode under `cast_opcodes`, 6
   fp↔int pairs, `variants: [fwd, inv, unc]` → **+18 symbols**.
2. `OpcodeSupport.cpp castInScope`: add
   `if (op == "bitcast") return (ff && ti && ff==ti) || (fi && tf && fi==tf);`
   (admits exactly the 6 pairs; int↔int is not admitted — it is folded).
3. Regenerate `runtime/cq_templates.{h,c}` (`gen_templates.py`); update the SHA
   drift banner and the `gen_templates_test.py` counts (2315 → 2333; cast count).
4. No `WidthDispatch`/`CastLowering`/`EmitInverse` change: `castName`/
   `castTemplateFn` build `cq_template_bitcast_<from>_to_<to>[_inv|_unc]`
   generically; the driver already collects `BitCastInst` and captures widths;
   uncompute reverses cast producers by name.

## Fixtures (Rule 12, red-green)

- **Positive** `lowering_bitcast_fp_to_int.ll`: `theta_f64 → bitcast f64→i64 →
  <int op> → bitcast i64→f64 → measure` → `cq_template_bitcast_f64_to_i64` +
  `cq_template_bitcast_i64_to_f64`.
- **Positive** `lowering_bitcast_f32_i32.ll`: the float-family `GET_FLOAT_WORD`
  round-trip.
- **Decline (re-pointed, PRESERVES the f64-angle coverage)**
  `lowering_reject_bitcast_angle.ll`: `theta → bitcast i64→double → cq_phi(q,
  <that double as arg-1>)` → declines `quantum-derived rotation angle` (the
  authoritative guard, not the bitcast guard).
- **Convert** the two `iw81.1` decline fixtures to positive lowering (their
  decline no longer holds); keep `lowering_reject_bitcast_select_stale.ll`
  (int↔int fold, unaffected) and the int↔int identity fixtures green.
- **Decline** `lowering_reject_bitcast_f80_i80.ll`: `bitcast x86_fp80↔i80`
  declines (no `i80` width).
